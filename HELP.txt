ЧТО УМЕЕТ ЭТА УТИЛИТА
----------------------------------------------------

Иконка в трее даёт доступ к 4 независимым способам работать с Claude:

1) Account 1 (Main) / Account 2 (Second)
   Два полностью независимых окна Claude Desktop с двумя разными
   аккаунтами Claude Pro, открытыми одновременно (изоляция через
   --user-data-dir). Для каждого: Open / Minimize / Close.

2) Open Gateway Terminal
   Терминал с Claude Code CLI, направленным через локальный шлюз
   OmniRoute (http://localhost:20128) на бесплатные/дешёвые модели
   (DeepSeek, OpenRouter, Gemini) — для рутинных технических задач,
   которые не требуют Sonnet/Opus.

3) Open Native Terminal
   Обычный терминал с Claude Code CLI на нативном Anthropic API
   (ваша подписка Claude Pro напрямую).

4) Local Models (llama.cpp)
   Список моделей сканируется живьём из папки C:\llama.cpp\models
   (<издатель>\<модель>\*.gguf, рядом mmproj-*.gguf для зрения) —
   что положите/удалите там, то появится/исчезнет в меню без
   перезапуска утилиты. Другую папку задаёт переменная LLAMACPP_MODELS_DIR.
     - Выбор модели (radio-список)
     - Start Server / Stop Server / Server Status — поднимает
       llama-server.exe локально на http://127.0.0.1:8080; к нему
       может подключиться любой OpenAI-совместимый харнесс (например,
       Hermes Agent — уже настроен на это).
       Все модели отдаются под одним и тем же фиксированным именем
       "local-model-llama-cpp", какой бы GGUF ни был на самом деле
       загружен — это сделано специально, чтобы Hermes и OmniRoute
       никогда не нужно было перенастраивать при смене модели.
     - Open Claude Code CLI (Local Model) [experimental] — тот же
       Claude Code CLI, но через OmniRoute направленный на локальную
       модель. Помечено experimental: системный промпт Claude Code на
       этой машине большой и нестабильный по размеру (37K-87K токенов
       замерено), из-за чего первое сообщение может быть медленным
       (30-90+ сек) или не пройти вовсе (ошибка "exceeds the available
       context size"). Подробности — README.md, часть 5.

КАКУЮ БРАТЬ ДЛЯ ЧЕГО

  Длинные многошаговые задачи в Hermes, браузер,
  computer_use, всё, где надо разбираться в ошибках
      -> Qwen3-VL-30B-A3B-abliterated  [tuned] [vision]
  Короткие задачи, когда важна скорость
      -> Qwen3-VL-8B-abliterated  [tuned] [vision]

Модели с пометкой [vision] умеют смотреть на картинки,
остальные - нет. Если отправить скриншот текстовой модели,
сервер ответит ошибкой "image input is not supported", и со
стороны это выглядит как будто агент тупит, хотя он просто
не получил изображение.

----------------------------------------------------
1) Huihui-Qwen3-VL-30B-A3B-Instruct-abliterated-Q4_K_M
   (17.3 ГБ) плюс mmproj-F16.gguf (1.0 ГБ)
----------------------------------------------------

Основная модель для Hermes. Архитектура Mixture-of-Experts:
около 30 миллиардов параметров всего, но на каждый токен
активны только три, поэтому скорость остаётся приемлемой даже
при частичной выгрузке в оперативную память.

Весов больше, чем видеопамяти, поэтому часть экспертов живёт
в RAM (флаг --n-cpu-moe). Из 128 экспертов на токен срабатывает
восемь, так что нагрузка на процессор заметно меньше, чем
можно предположить по объёму выгруженного.

Взята в Q4_K_M, а не в более лёгком кванте, сознательно:
квантование ниже Q4 в первую очередь портит следование
инструкциям, а ради него эта модель и ставилась.

Замеры на RTX 4080 SUPER при --n-cpu-moe 24:
  - 13.9 ГБ из 16.4 ГБ VRAM, запас 2.4 ГБ на обработку картинок
  - 30 токенов/с на тексте, 38 токенов/с со скриншотом
  - контекст 65536

Значение 24 подобрано замером, а не на глаз. При 18 модель
занимала 15.7 ГБ и выдавала 32 и 42 токена/с: 6-10 процентов
скорости обменены на 1.7 ГБ запаса, потому что обработка
изображения выделяет память поверх KV-кэша и 726 МБ для этого
мало. Если видеокарта ничем больше не занята, значение можно
уменьшить ради скорости.

----------------------------------------------------
2) Huihui-Qwen3-VL-8B-Instruct-abliterated-Q5_K_M (5.4 ГБ)
   плюс mmproj-F16.gguf (1.1 ГБ)
----------------------------------------------------

Быстрый вариант: целиком помещается в видеопамять вместе с
проектором (10.8 ГБ), выдаёт около 96 токенов в секунду.

Ограничение, ради которого и появилась модель на 30B: на
длинных задачах она перестаёт делать выводы из ответов
инструментов. В одной сессии Hermes дважды сработала защита
от зацикливания - модель повторяла вызов, уже вернувший
ошибку, пока её не остановили. Годится для коротких и чётко
поставленных задач.

----------------------------------------------------
ВАЖНО ПРО ПОДПИСКИ (ToS)
----------------------------------------------------

Ничего здесь не объединяет и не "пулит" ваши подписки Claude Pro в
обход условий использования Anthropic — каждое окно логинится
официально и по отдельности. Шлюз (пункт 2) и локальные модели
(пункт 4) используют только сторонние/локальные модели и никогда не
трогают ваш Anthropic OAuth токен.
